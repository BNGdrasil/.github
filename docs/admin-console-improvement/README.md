# 어드민 콘솔 개선 문서 패키지

기준일: **2026-09-22 KST**. 대상은 Bantheon의 관리자 콘솔(`admin/`)과 그 화면이 호출하는 Bifrost 관리자 API다. 상태는 **계획 확정, 구현 미착수**다.

2026-09 전면 보수에서 관리자 콘솔의 가짜 데이터를 제거한 결과, 화면은 실제로 동작하는 얇은 콘솔이 되었다. 다만 얇아진 만큼 운영자가 이 화면에서 할 수 있는 일이 줄었고, 콘솔의 의의가 무엇인지 다시 정리할 필요가 생겼다. 이 패키지는 그 판단과 후속 계획, 그리고 계획 대비 현재 코드의 상태를 기록한다.

## 읽는 순서

| 문서 | 용도 |
|---|---|
| [01 개선 계획](01-plan.md) | 2026-09-20에 확정한 역할 정의, 설계 원칙, 범위 제외 결정, 단계별 작업 계획 |
| [02 현황 점검 (2026-09-22)](02-status-2026-09-22.md) | 계획 항목별 구현 여부를 실제 코드에서 확인한 결과와 근거 위치 |

01을 먼저 읽어서 무엇을 왜 하기로 했는지 확인한 다음, 02에서 지금 어디까지 되어 있는지 확인하는 순서를 권한다.

## 이 패키지의 관리 원칙

- `operations-improvement` 패키지와 같은 기준을 따라서 "구현됨", "테스트됨", "운영 적용됨"을 서로 다른 상태로 구분해 기록한다. 테스트를 통과했다는 사실이 운영에 적용됐다는 뜻으로 번지지 않게 한다.
- 계획의 한 항목이 끝나면 02 문서의 해당 행에 검증 결과와 커밋 SHA와 운영 적용일을 기록한다. 세 가지 가운데 확인하지 못한 항목은 빈칸으로 두지 않고 확인하지 못했다는 사실을 적는다.
- 현황 점검을 다시 수행할 때에는 02 문서를 덮어쓰지 않고 `02-status-<날짜>.md` 형식으로 새 파일을 추가한다. 그렇게 해야 시점별 상태를 나중에 비교할 수 있다.
- 근거는 파일 경로와 줄 번호로 적는다. 줄 번호는 확인 시점의 값이므로 문서 안에 기준일을 함께 남긴다.
- 문서에는 비밀 값과 토큰과 공인 IP와 클라우드 자원 식별자를 적지 않는다.
